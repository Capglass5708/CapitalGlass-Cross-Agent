# VAE repo index — seed population proposal (v1)

**Work package:** `vae-repo-index-seed-population-v1`
**Owner repo for the change:** `Visual-Asset-Engine` (seed) + `CG-AppBuilder-MCP` (seed bank)
**Status:** PROPOSED — nothing here has been applied to either owning repo.

Cross-Agent is the coordination ledger. This folder holds the proposal and its evidence;
the seed itself must be applied in `Visual-Asset-Engine`, and the seed-bank override in
`CG-AppBuilder-MCP`. Do not treat `compiled-index-preview.v1.json` as publishable output.

## Why

`Visual-Asset-Engine/index/cg-federated-repo-index.v1.json` is provenance-correct as of
`44e121c` but semantically empty: `repoClass` is `unknown`, `authorities`, `capabilities`,
`protocols`, `surfaces` and `dependencies` are all `[]`, and `CODE_POINTERS` holds a single
entry for `README.md`. Consequences:

- VAE contributes **zero rows** to the estate capability index
  (`work-progress/intelligence-hub-slices/federated-capabilities.v1.json` carries 5
  capabilities from 3 repos; VAE is not one of them). The federated compiler reads the
  structured lowercase `capabilities[]`; the legacy uppercase `CAPABILITIES`
  (`["visual-asset-pipeline"]`) only feeds alias routing.
- VAE answers **no authority question**, so Luna identity routing can reach it by alias but
  cannot route any question to it.
- None of what the repo actually owns is described — it is the upstream authority for
  CG-MASTER-GRAPH's visual-intelligence extraction (PR #57), the sole Illustrator
  vector-trace engine, and the publisher of `@capglass5708/vae-tokens`.

The cause is the seed: `index/repo-index.seed.v1.json` omits `repoClass`,
`requireStructured` and `authorities`, so nothing forces structured population.

## The divergence this uncovered

There are **two** VAE seeds and they do not agree:

| | in-repo `index/repo-index.seed.v1.json` | banked `CG-AppBuilder-MCP registry/federated-repo-index/seed-bank/Visual-Asset-Engine.seed.v1.json` |
| --- | --- | --- |
| `repoClass` | *(absent → compiles to `unknown`)* | `engines` |
| `requireStructured` | *(absent)* | `true` |
| `authorities` | *(absent → `[]`)* | `visual-asset-engine-identity-v1` |
| `DOMAINS` | `visual-assets` | `engines` |
| `CAPABILITIES` | `visual-asset-pipeline` | `[]` |
| `PROGRAMS` | `vae-foundation-v1` | `[]` |
| `CODE_POINTERS` | `README.md` | `[]` |
| `ALIASES` | `vae`, `visual asset engine` | `visual-asset-engine`, `visual asset engine` |

`compileLocalIndex` reads the **in-repo** seed, so the bank is not what produced the current
index. But the bank is regenerated by `generate-seed-bank.mjs`, whose `RICH_OVERRIDES` table
has no `Visual-Asset-Engine` entry — VAE falls through to `baseSeed()` boilerplate. For
comparison, `CapitalGlass-Cross-Agent` has a `RICH_OVERRIDES` entry and its two seeds match
exactly.

**Risk:** if the bank is ever distributed to repos, VAE's routing content (domain
`visual-assets`, alias `vae`, program `vae-foundation-v1`) is overwritten with generic
`engines` boilerplate. Fixing only the in-repo seed leaves that trap armed.

## The fix is two-part

1. **`Visual-Asset-Engine`** — replace `index/repo-index.seed.v1.json` with
   [`proposed-seed.v1.json`](./proposed-seed.v1.json), then recompile the index on the
   governed host.
2. **`CG-AppBuilder-MCP`** — add [`proposed-seed-bank-override.v1.json`](./proposed-seed-bank-override.v1.json)
   as `RICH_OVERRIDES["Visual-Asset-Engine"]` in
   `scripts/federated-repo-index/generate-seed-bank.mjs`, so regenerating the bank
   reproduces the same seed instead of clobbering it.

The override carries exactly the 15 keys that differ from `baseSeed()`; the other 8 are
inherited. `{ ...baseSeed(repo), ...override, requireStructured: true }` reconstructs
`proposed-seed.v1.json` byte-for-byte (verified — see `validation-report.v1.json`).

## What the seed declares

Everything is grounded in files that exist at `44e121c`; nothing is aspirational.

- **3 authorities** — repo identity, visual generation (per `CLAUDE.md`: "this repo is the
  visual generation authority"), and the authoritative visual-intelligence graph (per the
  published packet's `provenance.sourceAuthority: authority:visual-asset-engine`).
- **5 capabilities**, each with a verified `implementation.path` and a real exported symbol:
  `visual_intelligence_graph_build_v1` (`buildVisualGraph`),
  `visual_intelligence_graph_publish_v1` (`publishVisualGraphPacket`),
  `visual_context_retrieval_v1` (`getVisualContext`),
  `illustrator_vector_trace_v1` (`vectorizeDocument`),
  `vae_read_only_mcp_tools_v1` (`callVisualAssetEngineMcpTool`).
- **3 protocols** — the proposal-cover hero dissolve, Illustrator visual authoring, and
  visual experience event contracts.
- **3 surfaces** — MCP server, CLI, pipeline status script.
- **1 dependency** — `CG-AppBuilder-MCP` as contract and governance authority, matching the
  authority hierarchy in VAE's own `CLAUDE.md`.
- **4 code pointers / 5 symbol pointers**, all resolving `PUBLISHED` / `clean`.
- `DOMAINS` stays `visual-assets` (the live estate route; VAE is its only member) while
  `repoClass` becomes `engines` (its tier in `registry/git-estate/git-estate-manifest.v1.json`).
  These are separate axes, which is how the bank/in-repo disagreement gets resolved without
  moving VAE out of its working route.
- `illustrator_vector_trace_v1` is marked `ACTIVE` with metadata recording that it is
  workstation-local (WESLEYDESK) and not run in CI, per `07-KNOWN-EXCEPTIONS.md`.

`LATEST_RECEIPTS` is deliberately left empty — no receipt path was verified, and inventing
one would be worse than leaving the gap. It is listed in `NEXT_ACTIONS`.

## Verification performed

The draft was compiled through the **real compiler**, fetched verbatim from
`CG-AppBuilder-MCP@04f81628db7cf0f67fd6a5a312835cda28a01f3b`, against a clone of
`Visual-Asset-Engine` at `44e121c`, with `requireStructured: true`.

- **Result: `COMPILE_PASS`.** `compileLocalIndex` throws `LOCAL_INDEX_INVALID` on a
  validation failure; it returned an index.
- All 9 pointers bind `PUBLISHED` / `clean`.
- Compiled `CAPABILITIES` becomes the sorted union of the legacy string and the 5 structured
  ids, which is how `CapitalGlass-Documents` and `CG-AppBuilder-MCP` already look.
- **Negative control:** four deliberately broken variants (missing implementation path,
  undeclared `authorityId`, surface without `kind`, duplicate `capabilityId`) were each
  rejected with the expected error, confirming the validator was genuinely exercised rather
  than passing vacuously.

Full evidence in [`validation-report.v1.json`](./validation-report.v1.json).

## Applying it

```bash
# 1. Visual-Asset-Engine
cp proposed-seed.v1.json  <VAE>/index/repo-index.seed.v1.json
cd <VAE> && node ../CG-AppBuilder-MCP/scripts/federated-repo-index/run-compile-local-index.mjs --repoRoot=.
node ../CG-AppBuilder-MCP/scripts/federated-repo-index/run-repo-index-ci-check.mjs --repoRoot=.

# 2. CG-AppBuilder-MCP — add the override, then confirm the bank regenerates unchanged
node scripts/federated-repo-index/generate-seed-bank.mjs
git diff --exit-code registry/federated-repo-index/seed-bank/Visual-Asset-Engine.seed.v1.json

# 3. Re-harvest the estate views so VAE's capabilities federate
node scripts/federated-repo-index/run-harvest-capability-index.mjs
node scripts/federated-repo-index/run-harvest-estate-routing.mjs
```

The index must be recompiled **on the governed host** — the preview here records
`hostname: vm`, `machineRole: null`, which is not publishable provenance.
